# V7：顺序操作块输入与脚本哈希链

当前实现替代 V6 的完整操作表选择。块大小仍为 32 字节，命令行参数不变。

## 从文件到证明

1. `diff` 读取两个文件，用 Myers 生成公开编辑脚本。原文承诺继续使用私有盐。
2. `Statement::circuit()` 调用 `chunks()`，把脚本拆成每块最多 32 字节的操作，再调用 `EditCircuit::statement()`。
3. `statement()` 在电路外计算公开新文承诺和公开脚本承诺。脚本承诺由公开 JSON 重新计算，不接受证明者自行指定的脚本摘要。
4. `setup` 使用固定形状电路生成密钥。原文长度、新文长度和块数仍是形状参数；块大小与哈希规则也必须一致。
5. `prove` 在 Nova 初始化前装入第一块；后续每步调用 `set_edit_step()`、`set_source_step()`、`set_target_step()`，分别准备当前操作、原文片段和新文片段。
6. `synthesize()` 检查类型、长度、字节范围、keep 相等和 insert 内容，推进三个游标及三条链。每步约束数量不随操作类型变化。
7. `verify` 从公开 JSON 重建初始状态，验证压缩证明，再调用 `completed()`。三个游标必须全部走完，三条链的最终值必须匹配公开承诺。

这里的“流式”指每步电路只接收当前块；命令行仍在内存中读取完整文件并运行 Myers，不是磁盘流式 Myers。

## 固定的 10 个状态元素

| 索引 | 内容 |
|---|---|
| 0、1、2 | 原文、新文、操作游标 |
| 3 | 原文总长度 |
| 4、5 | 新文承诺、新文链当前值 |
| 6、7 | 脚本承诺、脚本链当前值 |
| 8、9 | 原文承诺、原文链当前值 |

新文及脚本仍是公开输入，只是不再以全文或完整操作表形式放入递归状态。私有原文和盐仍不公开。

## 一个操作如何进入哈希链

`encode_edit()` 编码为 `[类型, 长度, 32 个插入字节槽]`：keep=0、delete=1、insert=2；未使用插入槽填零。

每块编码为三个域元素：

- `类型 + 3 × 长度`。类型只允许 0、1、2，所以不同合法类型和长度不会混淆。
- 前 16 个插入槽，按小端打包为 128 位整数。
- 后 16 个插入槽，同样打包。

电路约束每个槽是字节，128 位整数小于域模数，所以打包没有信息损失。每块依次计算三次 Poseidon，分别使用不同域标记；新结果作为下一块的起点。最后再把总块数哈希进去。所有插入槽（包括填零槽）均被绑定。

这会绑定拆分后的操作内容和顺序。零长度操作及相邻操作的原始 JSON 写法不一定唯一：绑定对象是 `chunks()` 规范拆分后实际执行的序列，不是 JSON 原始文本。

原文链、新文链、脚本链使用不同域标记。只有原文链使用盐；公开脚本不需要盐。删除或重排操作，即使最终文本相同，也不能通过脚本承诺检查（依赖 Poseidon 抗碰撞性）。

## 成本和兼容性

每步脚本哈希及打包增加 945 条业务约束，取代原来随块数增长的独热选择和逐列选择；状态从 `8 + 34 × 块数` 缩为 10。不能仅凭新增哈希判断 Nova 整体开销：Nova 自身还需要处理递归状态。

V7 密钥和证明使用新的格式标记，旧 V6 密钥不能复用，必须重新 setup。公开 JSON 和私有盐文件格式保持兼容。同长度、同块数的不同文本和脚本仍可复用 V7 密钥。约束数量相同不代表不同长度、不同块数的密钥能够互用。

测试覆盖原有端到端流程、密钥复用、错误盐、内容篡改，以及新增的操作重排、非零填充、脚本未执行完、1 块与 128 块状态和约束数相同。
